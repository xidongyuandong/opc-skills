# 验收与成本证据

## 用户可感知目标

同一个复杂任务中，事实采集可以并行；实现只进入限定文件；未经验收的结果不会成为后续任务依据。任务失败会保留原因并停止依赖链，而不是无限尝试或静默降级。

## 三层验证

1. 确定性合同：用 unittest 覆盖环、未知依赖、重复id、非法状态、主代理身份不匹配、容量、写入/读写冲突、未验收依赖、模型不可用、重试/上下文上限。证明调度输入到输出规则，不证明LLM质量。
2. 原生工具烟测：对已知证据做最小只读任务，按生成参数调用工具，主代理比对返回事实与源文件。记录requested model、工具返回、实际可见身份；工具未提供计费usage时unknown。
3. 配对效果评测：预先固定样本、版本、验收与预算，对单代理和本技能各跑同样任务。小查询、互不影响的双模块、同文件冲突、复杂规划、失败恢复都应覆盖。质量按需求符合、证据准确、缺陷与返工评价；统计所有失败，不能只挑成功案例。

## 指标口径

- 成功率：主代理独立验收通过的任务数 / 全部预注册任务数。
- 总token：主代理规划+每次子调用输入输出+失败重试+最终审查整合；缺失则unknown。
- token变化：(基线总token - 新总token) / 基线总token；基线必须大于0且两组采集完整。
- 费用：需要同日价格及缓存/推理token口径；低价模型与较少token是不同结论。
- 延迟：任务开始到最终验收的墙钟时间，包含排队、重试、合并。
- 质量非劣是降成本的前置条件；一次烟测不能推断所有任务都更好。

## 发布版验证边界

确定性测试和临时路径烟测只验证合同、编排机制与路径可移植性，不调用模型。未开展有计费usage的配对A/B，不宣称质量百分比或token节省。使用者需在实际运行环境补充工具兼容性与效果证据。
