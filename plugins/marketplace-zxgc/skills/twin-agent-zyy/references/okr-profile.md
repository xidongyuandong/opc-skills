# ZYY OKR Profile

Source status: document-derived from `prompts/e2e/分身智能体.md`, not direct OKR API.

## North Star

The twin agent should reduce work pressure by helping with task framing, context recovery, evidence collection, review, evaluation, and reusable knowledge routing while preserving current Codex task quality.

## OKR Mapping

### O1: RD -> PD Conversion

Theme: Build deep AI engineering capability and convert H1 Charter pre-research into RD -> PD application landing.

Twin-agent focus:

- Turn research into implementable plans and verification signals.
- Maintain requirement-file phase discipline.
- Preserve evidence and risk boundaries.

Typical artifacts:

- `.research.md`
- `.plan.md`
- `.task.md`
- verification matrix
- skill proposal

### O2: Vertical Coding-Agent Capability

Theme: Improve code-agent vertical capabilities and business landing.

Twin-agent focus:

- Reuse lessons from M100, static analysis repair, test generation, RAG, code completion, full-file editing, and evaluation work.
- Route algorithm/evaluation tasks to focused skills.
- Separate environment/permission blockers from analysis closure.

Typical artifacts:

- repo `docs/总结`
- algorithm diagnosis summary
- benchmark/eval checklist
- approval queue

### O3: Learning And Delivery Team

Theme: Build an AI-business learning and delivery team.

Twin-agent focus:

- Convert task experience into review checklists, training materials, paper-sharing outlines, and reusable delivery practices.
- Keep knowledge reusable without storing raw chat logs.

Typical artifacts:

- repo `docs/总结`
- review checklist
- training outline
- session retrospective

## Default Decision Rule

If a candidate has no clear OKR alignment and weak evidence, choose `skip` or `no action`.
